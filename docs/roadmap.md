## 一、现状判定

| 项 | 结论 |
| --- | --- |
| 主流程 | 能跑通：项目 / 科目 / 4 类付款节点 / 申请-开票-付款 / 验收与试运行联动 / 报表 / 合同识别 |
| 能否直接上线 | **不能（基线实测结论：不通过）**。代码评审 6 个 P0 / 9 个 P1 / 21 个 P2；基线实测 3 个 P0 / 11 个 P1 / 11 个 P2。两套口径互补，合并后才是完整清单 |

| 越权与安全实测 | 默认 SECRET_KEY 可伪造管理员会话（实测 200）；全站无 CSRF；经办人可删除项目、可经「编辑项目」改状态；默认弱口令无锁定 |
| 数据 | 种子节点存在「已付款但无付款记录」的台账矛盾；实例库已被 e2e 测试数据污染，需重置为干净种子库 |
| 环境 | Python 3.12、依赖已装；git 未安装（用快照替代）；SQLite 单文件，单机可跑 |

## 二、上线硬指标（阶段 1 验收）

1. 安全：无默认密钥/默认账号、全站 CSRF、权限矩阵全覆盖（viewer 只读、operator 不能改状态/删项目）
2. 金额：Decimal 全链路、服务端强校验（比例合计、正负、有限数）、节点应付合计与合同金额勾稽
3. 合同回改：不丢已开票/已付款数据、不 500、有审计、差异二次确认
4. 审计：登录、项目增删改、节点申请/开票/付款、合同确认/回改、用户管理可查 before/after
5. 备份：每日自动备份 + 恢复演练通过 + 失败告警
6. 迁移：旧 Excel 可导入、可回导对账；报表可导出 Excel

## 三、阶段与执行批次

**阶段 0 · 接管与基线（1-2 天）**
快照备份、依赖锁定、基线测试报告、部署环境调研、数据库重置与测试隔离。

**阶段 1 · 可安全上线最小闭环（1.5-2.5 周）**

| 批次 | 内容 | 主责 | 涉及文件 |
| --- | --- | --- | --- |
| 1 | 金额工具、全链路校验、并发原子更新（P0-3、P1-6、并发丢失更新 P0） | 开发 | `app/money.py`（新）、`app/validation.py`（新）、`app/routes.py`、`app/models.py` |
| 2 | 合同回改不丢数据、确认页回填现值（P0-1、P0-2） | 开发 | `app/routes.py:557-654`、`templates/contract_confirm.html` |
| 3 | 审计留痕 + 软删除（P0-4） | 开发 | `app/models.py`、`app/audit.py`（新）、`app/routes.py`、新模板 |
| 4 | 安全基线（P1-8、越权）：CSRF、密钥、改密、限速、错误页 | 开发 | `app/__init__.py`、`app/routes.py`、`templates/` |
| 5 | 部署与备份（P0） | 架构师 | `scripts/backup.ps1`、`scripts/restore.ps1`、`docs/deploy.md`、`docs/backup-restore.md` |
| 6 | Excel 导入 / 导出（P0-5、P0-6） | 开发 | `scripts/import_excel.py`、`scripts/export_excel.py` |

批次 1 → 4 有顺序依赖（1 先落地金额工具，2/3/4 复用）；5、6 可与代码批次并行。

**阶段 2 · 稳定与可维护（2-2.5 周，P1）**
分层重构（routes 拆 service）、并发与长事务（OCR 移出事务）、外键索引与约束、Alembic 迁移、pytest + CI、报表 SQL 化、数据库抽象（MSSQL 预留）。

**阶段 3 · 业务增强（1-1.5 周，P2）**
撤销/冲销、部分付款语义、审批流、附件、提醒、合同要素扩展、SSO 评估。

## 五、待用户决策（阻断阶段 1）

1. **旧 Excel 原件**：历史「已付款」是生成可追溯付款记录（含日期/凭证/发票号），还是只回填节点汇总金额？金额尾差归质保金还是单列？
2. **合规与部署**：有无等保/内控/审计留存年限/国产数据库要求？部署机器与并发人数？合同原文能否发外部大模型？
3. **部分付款**：实际业务是否存在「应付 3 万先付 1 万」？决定状态机是否重构。
4. **改价权限**：谁有权改合同金额/比例、回改已生成项目？是否要求申请—审批—付款分离？
5. **可见范围**：viewer 能否查看合同原文与金额？

## 六、主要风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 合同回改丢付款数据 / 500（已实测） | 财务数据事故 | 批次 2 必修；上线前数据快照 + 双轨核对 |

| Excel 口径与系统不一致 | 中高 | dry-run + 差异报告 + 业务签字 |

| 默认密钥 + 默认账号 + 无 CSRF | 高 | 批次 4 必修，上线前安全复检 |
