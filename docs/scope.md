# 功能范围与验收标准清单（逐项确认版）

- 版本：v1.0（2026-10-23）
- 用途：作为「替换 Excel 内部上线」的范围基线；每项标注 **现状 / 阶段 / 验收标准 / 待决策**，逐项确认后锁定，防止范围蔓延。
- 依据：`README.md`（现状）、`docs/review-technical.md`（评审）、`docs/roadmap.md`（批次）、`docs/fix-plan-p0.md`（P0 设计）
- 状态图例：✅ 已实现并通过基线验证；🟡 已实现但需修复/补验收（批次 1~3）；⛔ 未实现（阶段/批次标注）；❓ 待用户决策

---

## 0. 范围边界

**本项目只做**：单位内部付款进度台账（项目→科目→4 类付款节点→申请/开票/付款→验收/试运行→报表→合同识别生成台账），替换现行 Excel。

**明确不做（本期）**：财务总账/凭证（不替代用友等）、银行直连支付、发票查验/税控对接、多组织/多法人、移动 App、对外门户、OA 审批引擎（审批流仅评估，阶段 3）。

## 11. 非功能验收（上线门槛）

| 项 | 标准 |
| --- | --- |
| 安全 | 无默认密钥/账号；全站 CSRF；权限矩阵全绿；密码哈希 scrypt；HTTPS；审计不可改 |
| 数据准确性 | Decimal 全链路；比例/金额服务端强校验；明细与汇总一致；金额核对 100% 通过 |
| 并发 | 5~20 人；并发付款无丢失更新；OCR 上传期间按约定错峰（长事务阶段 2 修） |
| 性能 | 500 项目内页面 <3s；报表导出 <10s；备份 <30s（当前 1.9MB 数据量） |
| 可用性 | 服务崩溃自动拉起；恢复演练通过；RTO ≤1h、RPO ≤12h（按备份频率） |
| 合规 | 审计留存 ≥3 年；操作可追溯；数据不出内网（LLM 默认关） |
| 可运维 | 部署手册、备份恢复手册、账号清单、日志位置、升级回滚步骤齐备 |

## 15. 本轮确认带来的设计增量（协议）

1. **比例配置**：4 类节点（首付/进度/验收/质保）仍固定为类型，但 `ratio` 不再取常量；来源优先级 = 合同识别结果 → 用户手填；无默认值，未识别时输入框留空并提示必填。比例按**项目级**一套，应用到该项目所有科目（科目各自金额 × 比例）。**金额口径（2026-10-23 统一）**：所有节点（含首付）统一按「科目原金额+增补金额」× 比例计算，尾差归集后节点合计=合同总额；不再有"首付仅按原金额"特例。
2. **合同生成项目不再固定单科目**：合同确认页科目表支持任意多行（科目名、税率、原金额、增补金额），`Σ科目原金额` 需与识别/填写的合同金额勾稽（差额按尾差规则提示）；每科目按项目比例生成 4 节点。
3. **不自动生成项目编号**：合同确认页/新建项目页的项目编号（合同号）字段默认空、必填、`unique`；删除 `_next_contract_project_no()` 自动流水逻辑；建后不可改。
4. **无回归兼容要求**：现有种子库/测试数据里固定 30/52/15/3 的比例与节点名照常可读（历史数据不迁移比例）；新建/合同确认走新逻辑。
5. 涉及代码（开发执行，非本设计落地）：`app/__init__.py` NODE_TEMPLATES 仅保留类型/基数/触发语义；`routes.py` 项目新建/合同确认表单与校验；`contract_engine` 识别结果返回 `ratios=None` 时不回填默认值；`templates/` 项目表单与确认页；`validation.py` 加合计=100 与科目合计勾稽；`tests/` 补用例（识别到/未识别/手填/负比例/合计不足）。
6. **部分付款（2026-10-23 已定）**：状态机增加「部分付款」；`paid_amount` 继续由流水合计（不得手改）；每次登记付款校验 `本次 ≤ 应付-已付`；累计=应付自动置「已付款」，否则「部分付款」；并发付款用条件 UPDATE 保证不超付；报表进度按 `已付/应付`，状态列展示部分付款。
