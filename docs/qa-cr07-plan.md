## 一、③「付款节点管理」科目列为空 —— 已复现（确认为缺陷，非数据问题）

**复现步骤（100% 必现，与科目配置/项目数据无关）**

1. 用 `tests/qa_common.seed_db()` 建临时库（含种子项目 1 个、3 科目 12 节点），登录 admin。
2. `GET /projects/1`。
3. 看「付款节点管理」卡片表格第一列「科目」。

**现象**

- 页面：`科目` 列每行都为空，只剩可能存在的「已冻结」徽章（`<td>` 内只有 badge，没有文字）。
- 数据层正常：`PaymentNode.query.filter_by(project_id=1).all()[0].to_dict()['item_name'] == '设备费'`，`node.item.item_name == '设备费'`。
- 代码层：`app/models.py` 的 `PaymentNode`（第 141 行起）**没有** `item_name` 列或属性；`hasattr(PaymentNode, 'item_name') == False`，科目名只能通过反向关系 `node.item.item_name` 取得（`to_dict()` 第 243 行就是这么写的）。
- 模板层：`app/templates/project_detail.html:212` 写的是 `{{ n.item_name }}`，Jinja2 对 Undefined 静默渲染空串 → 永远空白。

**根因**：模板字段名写错，`n.item_name` 应为 `n.item.name`（加空值保护 `if n.item else ''`）。

**影响面**：只有项目详情「付款节点管理」表格受影响；导出 `app/exporter.py`、报表 `app/templates/reports.html` 用的是 `node.item.item_name`，不受影响。

**修复建议（一行）**：`app/templates/project_detail.html:212` 改 `{{ n.item.name if n.item else '' }}`；`n.item` 是 `ProjectItem.nodes` 的 backref，已 `selectin` 预加载，无 N+1 风险。

**验收用例（修复后加）**

- ① 种子项目详情每行科目列显示对应科目名（设备费/软件费/安装费），与导出首列一致。
- ② 多科目项目（新增 2 个科目）每个节点显示自己的科目名，不串科目。
- ③ 合同/识别回填生成的单科目项目（科目=合同价款）显示「合同价款」。
- ④ 页面不出现空 `<td>`：断言每行首列文本非空。

## 二、④ 回收站「彻底删除」—— 安全用例清单（口径已拍板，待实现后执行）

前置：现有软删除=回收站（`projects.deleted_at/deleted_by`），恢复路由已存在；④ 是**物理删除**，高风险。已拍板口径：仅管理员、二次确认且**必须输入项目名**、不可恢复、关联数据（申请/发票/付款/截图）一并删除、写审计日志、**仍在走付款的项目禁止彻底删除（只允许归档）**。按以下维度验收。

| 编号 | 维度 | 用例 | 期望 |
| --- | --- | --- | --- |
| ④-01 | 权限 | operator 调 `POST /projects/<id>/purge` | 403 或无按钮；项目仍在，审计无删除记录 |
| ④-02 | 权限 | viewer 同上 | 403；按钮不可见 |
| ④-03 | 权限 | 未登录 | 302 到登录页，库无变化 |

| ④-05 | 二次确认 | 不带确认字段/确认值不符直接 POST | 拒绝并提示，库无变化 |
| ④-06 | 二次确认 | 输入的项目名与该项目不一致（错字/换行/多空格） | 拒绝，库无变化；精确匹配（含 trim 规则写清） |
| ④-07 | 正常删除 | admin 软删除 + 输入正确项目名后彻底删除 | 项目及关联数据全部消失，列表/回收站都查不到 |
| ④-08 | 级联 | 关联：科目、节点、申请单、付款流水、发票、验收记录、合同文件、合同截图、变更/审计 | 全部级联删除，无外键残留；`node_action_tokens` 等无关表不受影响 |
| ④-09 | 文件 | 合同截图/上传文件磁盘目录 | 删除或明确保留策略（不留下可访问的孤立图） |

| ④-12 | 误删保护 | GET 删除页/接口不带 CSRF 或跨站 POST | CSRF 拒绝（若该会话启用） |
| ④-13 | 幂等 | 对同一 id 重复彻底删除 | 第二次 404/提示不存在，不 500 |
| ④-14 | 并发 | 两个 admin 同时彻底删除同一项目 | 一个成功一个提示不存在，无 500、无半删状态 |
| ④-15 | 提示文案 | 确认页 | 明确「不可恢复」「需输入项目名」「关联数据一并删除」「建议先导出备份」 |
