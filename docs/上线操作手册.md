# 付款进度管理系统 · 本机上线操作手册

- 适用：单位内网 Windows 单机（本机），5~20 人使用
- 对应代码版本：`e98eb0d`（回归基线 235 项全绿）
- 本机已装：Python 3.12、项目依赖（Flask/SQLAlchemy/pdfplumber/PyMuPDF 等）
- 两条路：**A 简单模式**（先手动跑，10 分钟）→ **B 正式模式**（装服务 + 定时备份）

> 全程在 PowerShell 里执行；没装 venv 的机器，直接用系统 Python 也能跑。

---

## 0. 目录规划（建议）

| 用途 | 路径 |
| --- | --- |
| 代码 | `C:\Apps\payment-progress-system`（也可先用现在的工作区目录） |
| 数据（正式） | `C:\ProgramData\PaymentSystem\data` |
| 备份 | `C:\ProgramData\PaymentSystem\backups` |
| 日志 | `C:\ProgramData\PaymentSystem\logs` |

> 数据目录不要放在代码目录里，也不要用 `C:\Program Files`（不可写）。

## A. 简单模式（先跑起来）

### A1. 准备目录和数据

```powershell
$Code = 'C:\Apps\payment-progress-system'      # 改成你的实际代码目录
$Data = 'C:\ProgramData\PaymentSystem\data'
New-Item -ItemType Directory -Force "$Data", 'C:\ProgramData\PaymentSystem\backups', 'C:\ProgramData\PaymentSystem\logs' | Out-Null
```

### A2. 生成密钥（复制输出，后面要用）

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

### A3. 初始化数据库（只建表和账号，不建演示项目）

```powershell
cd $Code
$env:SECRET_KEY = '<上一步生成的密钥>'
$env:DATA_DIR = $Data
$env:APP_ENV = 'production'
python scripts\init_db.py --no-seed
```

成功标志：创建了 `payment_progress.db`、3 个账号（admin / jbr / viewer）。

### A4. 手动启动尝鲜

```powershell
cd $Code
$env:SECRET_KEY = '<密钥>'
$env:DATA_DIR = $Data
$env:APP_ENV = 'production'
python -m waitress --listen=127.0.0.1:8080 --threads=8 --connection-limit=100 run:app
```

浏览器打开 <http://127.0.0.1:8080>，用 `admin / admin123` 登录，**马上改密码**（右上角或登录后提示）。

### A5. 验证四件事

```powershell
# 1) 健康检查应为 200
Invoke-WebRequest http://127.0.0.1:8080/healthz -UseBasicParsing | Select-Object StatusCode

# 2) 手动备份（自动校验完整性）
powershell -NoProfile -ExecutionPolicy Bypass -File $Code\scripts\backup.ps1 -PythonExe (Get-Command python).Source

# 3) 跑一遍回归（应全绿，235 项）
cd $Code; $env:PYTHONIOENCODING='utf-8'; $env:PYTHONUTF8='1'; python tests\run_qa.py

# 4) 合同扫描件：登录后在「合同识别」上传一张扫描件 PDF/图片，确认能识别出金额并生成项目
```

> 简单模式重启电脑后要手动再启动一次；不想手动就做 B。

## B. 正式模式（服务 + 定时备份）

### B1. 下载 NSSM（一次）

下载 <https://nssm.cc/download> 的 zip，解压出 `nssm.exe` 放到 `C:\Tools\nssm\nssm.exe`。

### B2. 注册为 Windows 服务

**以管理员身份**打开 PowerShell：

```powershell
$Code = 'C:\Apps\payment-progress-system'
$Data = 'C:\ProgramData\PaymentSystem\data'
$nssm = 'C:\Tools\nssm\nssm.exe'
$secret = '<你的密钥>'

& $nssm install PaymentSystem "$Code\.venv\Scripts\waitress-serve.exe" `
  '--listen=127.0.0.1:8080 --threads=8 --connection-limit=100 run:app'
& $nssm set PaymentSystem AppDirectory $Code
& $nssm set PaymentSystem AppStdout 'C:\ProgramData\PaymentSystem\logs\waitress-out.log'
& $nssm set PaymentSystem AppStderr 'C:\ProgramData\PaymentSystem\logs\waitress-err.log'
& $nssm set PaymentSystem AppRotateFiles 1
& $nssm set PaymentSystem AppRotateOnline 1
& $nssm set PaymentSystem AppRotateBytes 10485760
& $nssm set PaymentSystem Start SERVICE_AUTO_START
& $nssm set PaymentSystem AppEnvironmentExtra `
  "SECRET_KEY=$secret" "DATA_DIR=$Data" "APP_ENV=production" `
  'PAYMENT_BACKUP_DIR=C:\ProgramData\PaymentSystem\backups'
& $nssm start PaymentSystem
Get-Service PaymentSystem
```

> 没做 B1 里的 venv 时，`waitress-serve.exe` 路径改为 `(Get-Command waitress-serve).Source`。

### B3. 每天自动备份（管理员）

```powershell
$Code = 'C:\Apps\payment-progress-system'
$py = (Get-Command python).Source
schtasks /Create /TN "PaymentSystem\Backup-1230" /TR "powershell -NoProfile -ExecutionPolicy Bypass -File $Code\scripts\backup.ps1 -PythonExe $py" /SC DAILY /ST 12:30 /RU "SYSTEM" /RL HIGHEST /F
schtasks /Create /TN "PaymentSystem\Backup-1830" /TR "powershell -NoProfile -ExecutionPolicy Bypass -File $Code\scripts\backup.ps1 -PythonExe $py" /SC DAILY /ST 18:30 /RU "SYSTEM" /RL HIGHEST /F
schtasks /Query /TN "PaymentSystem\Backup-1230" /V /FO LIST
```

备份在 `C:\ProgramData\PaymentSystem\backups\`，日志在同目录 `logs\backup-*.log`。

### B4. 首次登录配置

1. `admin` 登录 → 改密码 → 新建经办/查看账号
2. 停用不用的示例账号（jbr / viewer）
3. 建第一个真实项目

### B5. （可选）局域网 HTTPS

只在 `127.0.0.1` 本地用不需要；要让别的电脑访问，用 IIS ARR 或 nginx 反向代理到 `http://127.0.0.1:8080`，证书用单位 CA 签发的。不要直接暴露 8080。

## D. 常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 `SECRET_KEY` 相关错误 | 没设密钥或长度 < 32 / 用的是默认值 | 按 A2 生成，设为系统环境变量或 NSSM 参数 |
| 启动报 `DATA_DIR` 不可写 | 目录不存在或权限不足 | 建目录并给运行账号修改权限 |
| 启动 500 / `/healthz` 503 | 数据库文件缺失或损坏 | 停服务，用备份恢复后启动 |
| 页面正常但保存报 `database is locked` | 有人正在上传大扫描件，写锁占用 | 等识别结束重试；约定同一时段只一人扫描上传 |
| 扫描件识别失败 | OCR 文件访问/语言包问题 | 看日志错误分类；本机已验证可用，换清晰图片重试 |
| 服务起不来反复重启 | NSSM 日志里看 stderr | 按日志修复配置，再 `nssm restart PaymentSystem` |

## E. 升级与回滚

1. 升级前手动备份：`scripts\backup.ps1`
2. 停服务：`nssm stop PaymentSystem`
3. 覆盖新代码（保留 `data`、`backups`、`logs` 不动）
4. 若新版本要求改表：按发布说明跑 `scripts\init_db.py` 相关步骤（当前版本自动幂等补列，启动即生效）
5. 起服务，跑 `tests\run_qa.py` 冒烟，登录检查
6. 回滚：停服务 → 换回旧代码 → 若数据结构变过，用升级前备份恢复数据 → 起服务
