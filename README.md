# 付款进度管理系统（网页版）

按项目维度管理付款进度的轻量网页系统，业务口径与《付款进度表（新增动设备监测）.xlsx》一致。
技术栈：Python 3 + Flask + SQLAlchemy + SQLite（政务蓝白风格界面，单机即可运行，便于后续迁移 MSSQL）。

---

## 一、功能总览

| 模块 | 功能 |
| --- | --- |
| 项目管理 | 新建项目（多个费用科目）、编辑基本信息、搜索/筛选、状态流转（进行中/已完成/已归档）、删除项目（级联清除关联数据，不可恢复） |
| 付款节点 | 每个科目自动生成 4 类付款节点：首付款 30%、进度款 52%、验收款 15%、质保金 3% |
| 金额口径 | 首付款按**科目原金额**计算；进度款/验收款/质保金按**科目原金额+增补金额**计算 |
| 付款流转 | 发起申请 → 登记发票 → 登记实际付款，状态：未触发 → 未开票已申请 → 已申请 → 已付款 |
| 验收登记 | 登记验收日期后自动联动验收款节点，并自动推算质保到期日（验收日期 + 3 年，即 365×3 天） |
| 试运行登记 | 登记试运行日期后自动联动进度款节点触发日期 |
| 报表中心 | 按项目汇总应付/已开票/已付款/未付金额与付款进度，展示质保到期、待付款等提醒 |
| 用户管理 | 管理员可增删用户，角色分管理员 / 经办人 / 查看人员 |
| 合同上传识别 | 上传 PDF/Word/TXT/Markdown/图片合同，本地解析文本并识别金额、税率、付款方式与付款节点比例，人工核对确认后一键生成项目与付款节点；已确认合同可再次打开确认页修改比例/金额并重新生成（更新原项目，不新建） |

## 二、环境要求

- Python 3.10+（开发验证环境为 3.13）
- 无需额外数据库，使用 SQLite 单文件存储
- 文本解析依赖：`pdfplumber`（PDF）、`python-docx`（Word）、`PyMuPDF`（扫描件 PDF 逐页转图片）；图片/扫描件合同使用 Windows 自带 OCR（`scripts/ocr_win.ps1`），无需联网

## 三、快速启动

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 初始化数据库（含种子项目与默认账号）
python scripts/init_db.py

# 3. 启动服务（代码默认端口 5000；若被其他程序占用，用 --port 指定，如 5001）
python run.py --port 5001

# 4. 浏览器访问
# http://127.0.0.1:5001
```

> 如需清空数据重新初始化：`python scripts/init_db.py --force`

## 五、种子项目说明

初始化脚本内置种子项目 **PJ-2025-DSJ 新增动设备监测项目**，迁移自《付款进度表（新增动设备监测）.xlsx》：

| 科目 | 税率 | 原金额 | 首付款30%（按原金额） | 进度款52% | 验收款15% | 质保金3% |
| --- | --- | --- | --- | --- | --- | --- |
| 设备费 | 13% | 131,000 | 39,300 | 68,120 | 19,650 | 3,930 |
| 集成服务费 | 6% | 28,000 | 8,400 | 14,560 | 4,200 | 840 |
| 两年物联网卡 | 6% | 6,000 | 1,800 | 3,120 | 900 | 180 |
| **合计** | — | **165,000** | **49,500** | **85,800** | **24,750** | **4,950** |

按原始表格迁移：首付款 3 笔均已付款、进度款 3 笔已开票并处于已申请状态；试运行日期 2025-11-04 已回填。
**质保口径**：质保金应付日期 = 验收日期 + 365×3 天（1095 天），与原始 Excel 公式 `N3+365*3` 一致。
例如验收日期 2026-03-10 → 质保到期 2029-03-09（跨 2028 闰年，比日历加 3 年差 1 天）。

## 六、合同上传识别模块

### 6.1 操作流程

1. 顶部导航进入「合同识别」，点击上传合同文件（支持 `.pdf` / `.docx` / `.txt` / `.md` 与图片 `.jpg` / `.jpeg` / `.png` / `.bmp` / `.webp`，单个文件不超过 20MB）；
2. 系统本地解析文本并自动识别：合同总金额（含中文大写）、税率、付款方式、付款节点名称与比例；**扫描件/图片型 PDF 会自动调用 Windows OCR 识别文字，无需手动转换**；
3. 进入确认页：识别字段均可人工修改，每个识别字段下方回显**识别出处**（原句摘录）；节点比例可编辑，金额按比例实时联动，合计不等于 100% 时红色警示；
4. 点击「确认并生成项目」：自动创建项目与「合同价款」科目，生成首付款/进度款/验收款/质保金 4 个付款节点（首付款按合同金额，其余按合同金额 + 增补金额 × 比例）；
5. 合同列表对已确认合同提供「修改」入口：点击后重新打开确认页，改动比例/金额并提交，系统会**更新原项目的科目与付款节点**，不会新建重复项目；
6. 直接对同一合同重复提交确认会被拦截（不新增项目）；「重新识别」仅更新识别结果、不退回待确认状态。

### 6.2 识别引擎配置

识别引擎为纯本地规则引擎，默认不依赖任何外部 API。识别字段的抽取规则与出处见 `app/contract_engine.py`（识别逻辑沿用行政事业单位合同常见表述，如「合同总金额人民币壹拾陆万伍仟元整」「首付30%预付款+进度款52%...」等）。

如希望使用大模型提升复杂合同识别率，可通过环境变量配置 OpenAI 兼容接口（配置后优先使用，失败自动降级规则引擎）：

| 环境变量 | 说明 |
| --- | --- |
| `CONTRACT_LLM_ENDPOINT` | 兼容接口地址，如 `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `CONTRACT_LLM_API_KEY` | API Key |
| `CONTRACT_LLM_MODEL` | 模型名，如 `qwen-plus` / `deepseek-chat` |
| `CONTRACT_LLM_TIMEOUT` | 超时秒数（默认 60） |

### 6.3 样例合同

`scripts/samples/` 内置样例合同《合同样例-设备采购》（.txt 与 .docx 内容一致）：信息化设备采购，合同总金额人民币壹拾陆万伍仟元整（¥165,000.00），税率 13%，付款方式为「首付30%预付款+进度款52%+验收款15%+质保金3%」，用于演示与回归验证。

## 七、目录结构

```
payment-system/
├── app/
│   ├── __init__.py        # 应用工厂、付款节点模板、SQLite WAL 配置
│   ├── models.py          # 数据模型：用户/项目/科目/节点/申请/付款/验收/合同文件
│   ├── contract_engine.py # 合同识别引擎：本地文本提取 + 规则识别 + LLM 适配器
│   ├── routes.py          # 路由与业务逻辑（含合同上传/确认/重新识别/原文预览）
│   ├── static/css/        # 政务蓝白风格样式
│   └── templates/         # 页面模板（登录/项目/详情/报表/用户/合同三页）
├── scripts/
│   ├── init_db.py         # 初始化/重置数据库
│   ├── e2e_test.py        # 端到端验证脚本（93 项检查）
│   ├── e2e_scan_pdf.py    # 扫描件/图片型 PDF 端到端验证脚本
│   ├── ocr_win.ps1        # Windows 自带 OCR（图片合同识别）
│   └── samples/           # 合同样例（txt/docx）
├── requirements.txt
└── run.py                 # 启动入口
```

## 八、运行验证

服务启动后，可执行端到端验证脚本确认关键流程正常：

```bash
python scripts/e2e_test.py
```

脚本覆盖：登录、节点金额计算、新建项目、申请-发票-付款三态流转、试运行/验收联动、质保日期推算、报表、权限控制、数据落地、**合同识别闭环（上传 TXT/DOCX → 识别 → 确认页联动 → 确认生成 4 节点 → 重复确认拦截 → 重新识别 → 原文预览）**、**合同确认后回改并重新生成（更新原项目、不新建）**、**项目删除与关联数据清理（含查看人员删除权限拒绝）**及合同权限控制，全部通过输出“端到端验证全部通过”。

扫描件/图片型 PDF 的识别闭环另用专项脚本验证：

```bash
python scripts/e2e_scan_pdf.py
```

## 九、说明与限制

- 数据库文件位于 `instance/payment_progress.db`，由系统自动创建；已开启 WAL 模式与写入等待超时，多请求并发写入更稳健。
- 金额统一展示为千分位两位小数（如 39,300.00）。
- 本系统为项目内网/单机使用场景设计，未内置 HTTPS 与外部邮件等；如部署到公网，请自行配置反向代理与强密码。
